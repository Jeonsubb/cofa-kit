# 위임 프롬프트 패턴

`< >` 부분만 채워서 쓴다. 한 번에 하나의 작업만 맡긴다.

## 1. 작업 시작 전 계획 확인
```
AGENTS.md를 읽고, 성공 기준 <S1>을 달성하기 위한 구현 계획을 5단계 이내로 제안해.
각 단계마다 바꿀 파일, 검증 방법, 예상 위험을 적어. 아직 코드는 쓰지 마.
```

## 2. 작은 단위 구현
```
계획의 <N>단계만 구현해.
- 범위: <파일/함수>
- 완료 조건: <입력 X에 대해 Y를 반환>, 관련 테스트 추가 후 실행
- 범위 밖 변경 금지. 끝나면 변경 파일, 이유, 테스트 결과를 3줄로 보고해.
```

## 3. 이해 확인 (커밋 전)
```
방금 작성한 <함수/파일>에 대해 답해:
1) 이 구조를 고른 이유와 버린 대안
2) 실패하거나 잘못된 결과를 낼 수 있는 입력 3가지
3) 그때 사용자에게 보이는 현상
```

## 4. 실패 증거로 수정 요청
```
<입력>을 넣었을 때 기대값은 <A>인데 실제로 <B>가 나왔다(<재현 명령>).
원인을 먼저 설명하고, 테스트를 지우거나 기준을 완화하지 말고 수정해.
```

## 5. 교차 리뷰 (새 세션에서)
```
너는 이 저장소의 리뷰어다. AGENTS.md의 성공 기준 대비
1) 충족하지 못한 기준 2) 버그 가능성 3) 보안·개인정보 위험 4) 테스트 공백
을 심각도 순으로 근거(파일:줄)와 함께 나열해. 코드는 수정하지 마.
```

## 6. 문서 갱신
```
지금까지의 커밋과 대화를 바탕으로 docs/decisions.md에 빠진 결정을 추가하고,
docs/handoff.md를 실제 코드와 일치하게 갱신해. 코드에 없는 기능을 적지 마.
```
