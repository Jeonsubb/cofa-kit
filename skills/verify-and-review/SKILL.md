# 검증과 리뷰

## 1. 성공 기준 점검
- `AGENTS.md`의 성공 기준을 하나씩 읽고, 각각을 **실제로 실행하는 명령이나 입력**으로 확인한다.
- 결과를 `docs/verification.md` 표에 기록한다: 확인 방법, 기대 결과, 실제 결과, 판정(통과/부분/실패).
- 실행하지 않은 확인을 "통과"로 적지 않는다.

## 2. 테스트
- 전체 테스트를 실행하고 통과/실패 개수를 기록한다.
- 경계 케이스가 빠져 있으면 추가를 제안한다: 빈 입력, 잘못된 형식, 중복, 매우 큰 입력, 결측값, 시간대·정렬 순서.
- 테스트를 지우거나 기대값을 바꿔서 통과시키지 않는다.

## 3. 결함 찾기 (리뷰어 관점)
심각도 순으로, 근거(파일:줄)와 함께 나열한다. 이 단계에서는 코드를 고치지 않는다.
1. 충족하지 못한 성공 기준
2. 잘못된 결과를 낼 수 있는 입력과 그때 사용자에게 보이는 현상
3. 보안·개인정보 위험
4. 테스트 공백
5. 문서와 실제 코드가 다른 부분

## 4. 보고
- 고칠 것 / 지금 고치지 않을 것(이유) / 검증하지 못한 것을 나눠 보고한다.
- 사람이 고칠 항목을 고르면, 하나씩 수정하고 재검증한다.
- 수정한 내용은 `docs/decisions.md`의 "AI 산출물에서 바로잡은 것" 표에 남긴다.
