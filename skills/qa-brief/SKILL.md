# 후속 질문 대비 브리프

결과는 `docs/qa-brief.md`에 쓴다. 사람이 제출 직전 2~3분 안에 읽고 **자기 말로 답할 수 있게** 만드는 것이 목적이다. 사람이 대신 외울 모범답안이 아니라, 실제 기록에서 뽑은 근거 요약이다.

## 작성 전 읽을 것
`git log --oneline`, `AGENTS.md`, `docs/agreement.md`, `docs/decisions.md`, `docs/ai-judgment-log.md`, `docs/architecture.md`, `docs/verification.md`, 핵심 소스 파일, 테스트 목록.

## 질문별 항목 (각 항목 3~5줄, 근거는 파일:줄 또는 커밋 해시)
1. **핵심 설계 선택**: 무엇을, 왜, 버린 대안과 버린 이유, 감수한 제약
2. **요청 흐름**: 사용자 요청부터 결과 저장·표시까지 구성 요소 순서와 각 책임
3. **범위**: 구현됨 / 가정으로 두고 구현 / 구현하지 않음
4. **특이 케이스와 취약점**: 처리 중 변경·중복 요청·실패 시 동작, 단순 구현과 달라지는 점, 남은 취약점
5. **검증**: 결과가 규칙·목표를 지키는지 무엇으로 확인했나(별도 검사기, 기준선 비교, 테스트), 숫자
6. **미검증 위험**: 아직 확인 못한 것, 확인하려면 필요한 입력·데이터와 볼 지표
7. **까다로운 케이스**: 무엇이 어려웠고 어떻게 발견·해결·확인했나
8. **AI 판단**: 수용 / 수정 / 폐기 각각 대표 사례 1개씩, 근거와 계기
9. **검증할 때 중요하게 본 것**: 실제로 한 행동 기준으로

## 규칙
- 코드·기록에 없는 내용은 쓰지 않는다. 근거가 없으면 해당 항목에 **"기록 없음 — 사람이 확인 필요"**라고 적는다.
- 문서와 코드가 다르면 코드 기준으로 쓰고, 불일치를 맨 위 "주의" 섹션에 적는다.
- 숫자(건수, 시간, 통과 개수)를 우선한다.
- 전체를 1페이지 안팎으로 유지한다.
