# 후속 질문 은행과 답변 틀

AI 없이, 복사·붙여넣기 없이 답한다. 문항당 약 5분 → **2~4문장, 숫자 포함, 핵심부터**.
질문의 전제가 실제 구현과 다르면 **그 차이를 먼저 밝힌다**.

## A. 작업 중 질문 (AI 협업 과정)
| 질문 유형 | 답변 틀 | 근거 문서 |
|---|---|---|
| 까다로운 케이스와 해결 | 상황(입력) → 무엇이 문제였나 → 어떻게 발견했나 → 해결 → 어떤 테스트로 확인 | decisions.md 까다로운 케이스 |
| AI 답변 검증에서 중요한 것 | 원칙 1~2개 → 실제로 한 행동(원본 대조, 별도 검사기, 경계 테스트) → 그 결과 잡아낸 것 | ai-judgment-log.md 판정 기준·중요하게 본 것 |
| AI 답변을 실제와 비교해 개선한 것 | AI가 낸 것 → 실제(데이터·실행 결과)와 다른 점 → 어떻게 알았나 → 바꾼 내용 → 재확인 | ai-judgment-log.md 수정 |
| 수용/수정/폐기와 근거·계기 | 수용 1개(왜 믿었나) · 수정 1개(무엇을 왜) · 폐기 1개(왜 버렸나), 각각 계기 | ai-judgment-log.md |

## B. 제출 후 서술형
| 질문 유형 | 답변 틀 | 근거 문서 |
|---|---|---|
| 설계 이유·버린 대안·감수한 제약 | 선택 → 이유(근거) → 대안과 버린 이유 → 감수한 제약 | decisions.md D# |
| 요청에서 저장까지 흐름과 책임 | 1단계(구성 요소: 책임) → 2단계 → … → 저장·응답 | architecture.md |
| 구현 범위·가정·미구현 | 구현됨 / 가정으로 둔 것 / 구현 안 함, 각각 이유 | handoff.md 범위 현황 |
| 계산 위치·비동기 설계, 특이 케이스, 취약점 | 왜 그 위치·방식인가 → 특이 케이스에서 어떻게 동작하고 기존과 무엇이 다른가 → 취약점 | architecture.md |
| 결과가 규칙·목표를 지키는지 확인 | 별도 검사기로 규칙 R1~Rn 위반 0건 → 기준선 대비 지표 → 경계 입력 결과 → 확인 못한 부분 | verification.md 2절 |
| 미검증 위험과 확보할 입력·지표 | 위험 → 왜 아직 못 봤나 → 필요한 입력·데이터 → 볼 지표와 기준 | verification.md 5절 |

## 공통 답변 틀
- 약점형: **약점 지점 → 왜 위험한가(파급) → 다음에 무엇을 검증·개선할 것인가**
- 근거형: **주장 → 근거(숫자·파일·테스트) → 한계**
